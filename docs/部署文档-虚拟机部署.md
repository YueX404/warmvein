## 1. 前置条件

### 宿主机软件
- [VMware Workstation 17+](https://www.vmware.com/products/workstation-pro.html)（或 VMware Player 免费版）
- [Ubuntu Server 22.04 LTS ISO](https://releases.ubuntu.com/22.04/)（推荐 Server 版，无桌面更轻量）
- SSH 工具（Windows 自带 OpenSSH，或用 MobaXterm / Xshell）

### 虚拟机规划

| 资源 | 分配值 | 宿主机保留 | 说明 |
|---|---|---|---|
| CPU | **4 核** | 4 核（8 核剩余） | JVM 不吃核，4 核够用 |
| 内存 | **8 GB** | 8 GB（16GB 剩余） | 安全底线，需配合 JVM 堆优化 |
| 硬盘 | **80 GB（D 盘）** | D 盘剩余 36GB | C 盘仅剩 13GB，必须放 D 盘 |
| 网络 | NAT 模式 | — | 最简单，VM 自动获取 IP |
| 系统 | Ubuntu 22.04 LTS Server | — | 无桌面，最轻量 |

### 端口规划（宿主机 → 虚拟机）

以下端口在 VMware NAT 模式下需要端口转发（见 §2.6）：

| 服务 | 虚拟机端口 | 宿主机访问地址 | 用途 |
|---|---|---|---|
| Kafka | 9092 | localhost:9092 | 消息队列 |
| HDFS Web | 9870 | localhost:9870 | HDFS 管理界面 |
| Hive Server2 | 10000 | localhost:10000 | Hive JDBC |
| Hive Metastore | 9083 | localhost:9083 | 元数据服务 |
| Elasticsearch | 9200 | localhost:9200 | 搜索引擎 |
| Spark Master | 8080 | localhost:8080 | Spark 管理界面 |
| MySQL | 3306 | localhost:3306 | 业务数据库 |
| Redis | 6379 | localhost:6379 | 缓存 |
| PostgreSQL | 5432 | localhost:5432 | Hive 元数据库 |
| FastAPI | 8000 | localhost:8000 | 后端 API |
| Vite Dev | 5173 | localhost:5173 | 前端开发服务器 |

## 2. 创建 VMware 虚拟机

### 2.1 打开 VMware → 文件 → 新建虚拟机

选择 **"典型（推荐）"** → 下一步。

### 2.2 安装来源

选择 **"稍后安装操作系统"** → 下一步。

### 2.3 客户机操作系统

- 客户机操作系统：**Linux**
- 版本：**Ubuntu 64 位**
→ 下一步

### 2.4 命名与位置

- 虚拟机名称：`warmvein-ubuntu`
- 位置：**D:\VMs\warmvein-ubuntu**（⚠ 必须放 D 盘，C 盘空间不足）
→ 下一步

### 2.5 磁盘容量

- 最大磁盘大小：**80 GB**
- 选择 **"将虚拟磁盘拆分成多个文件"**
→ 下一步

### 2.6 自定义硬件

点击 **"自定义硬件"**：

**内存：** 拖动滑块到 **8192 MB (8 GB)**

**处理器：**
- 处理器数量：**2**
- 每个处理器的内核数量：**2**
- 总计：2 × 2 = **4 核**
- 勾选 **"虚拟化 Intel VT-x/EPT 或 AMD-V/RVI"**

**网络适配器：**
- 选择 **"NAT 模式"**
- 点击 **"NAT 设置"** → **"添加端口转发"**，逐条添加上面端口规划表中的所有端口（宿主机端口 → 虚拟机端口），格式如：
  - TCP | 9092 | 192.168.x.x | 9092
  - TCP | 9870 | 192.168.x.x | 9870
  - …（等 VM 安装完后获取到 IP 再补全也行）

**新 CD/DVD：**
- 选择 **"使用 ISO 镜像文件"**
- 浏览选择下载好的 `ubuntu-22.04.x-live-server-amd64.iso`
- 勾选 **"启动时连接"**

**USB 控制器：** 保持默认（USB 3.1）

**声卡/打印机/显示器：** 移除（减少资源占用）

→ 关闭 → 完成

## 3. 安装 Ubuntu 22.04

### 3.1 启动虚拟机

双击 `warmvein-ubuntu` 启动，进入 Ubuntu 安装界面。

### 3.2 安装过程关键步骤

| 步骤 | 操作 |
|---|---|
| Language | English（推荐，Docker 文档兼容性最好） |
| Keyboard | English (US) |
| Network | DHCP 自动获取（保持默认） |
| Proxy | 留空 |
| Mirror | 保留默认或改为清华源：`https://mirrors.tuna.tsinghua.edu.cn/ubuntu` |
| Disk | Use an entire disk → Done（80GB 全部分配） |
| Profile | 设置用户名/密码/主机名，例如：`warmvein` / `warmvein123` / `warmvein-vm` |
| SSH | **✅ 勾选 Install OpenSSH server**（必须勾选，方便远程连接） |
| Featured Snaps | 跳过，不选任何 snap |

→ Confirm install → 等待安装完成 → **Reboot Now**

### 3.3 安装后首次登录

```bash
# 查看虚拟机 IP
ip addr show | grep "inet " | grep -v 127.0.0.1
# 输出类似：inet 192.168.x.x/24 brd ... scope global ens33
```

在 **宿主机 PowerShell** 中测试 SSH：
```powershell
ssh warmvein@192.168.x.x
```

### 3.4 补全 VMware NAT 端口转发

VM 安装完后拿到真实 IP（如 `192.168.x.x`），回到 VMware → 编辑 → 虚拟网络编辑器 → NAT 设置 → 端口转发，补全 §1 中所有端口（宿主机端口 → 虚拟机 IP:端口）。

## 4. 安装 Docker + Docker Compose

在虚拟机 SSH 会话中执行：

### 4.1 更新系统

```bash
sudo apt update && sudo apt upgrade -y
```

### 4.2 安装依赖

```bash
sudo apt install -y ca-certificates curl gnupg lsb-release
```

### 4.3 添加 Docker 官方 GPG key

```bash
sudo mkdir -m 0755 -p /etc/apt/keyrings
curl -fsSL https://download.docker.com/linux/ubuntu/gpg | sudo gpg --dearmor -o /etc/apt/keyrings/docker.gpg
```

### 4.4 添加 Docker apt 源

```bash
echo \
  "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.gpg] https://download.docker.com/linux/ubuntu \
  $(lsb_release -cs) stable" | sudo tee /etc/apt/sources.list.d/docker.list > /dev/null
```

### 4.5 安装 Docker Engine

```bash
sudo apt update
sudo apt install -y docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin
```

### 4.6 允许非 root 用户使用 Docker

```bash
sudo usermod -aG docker $USER
newgrp docker
```

### 4.7 验证安装

```bash
docker --version
# Docker version 24.x 或 25.x

docker compose version
# Docker Compose version v2.x

# 运行测试容器
docker run --rm hello-world
# 看到 "Hello from Docker!" 即成功
```

## 5. 传输项目文件到虚拟机

有三种方式，选一种：

### 方式 A：Git Clone（推荐，最简单）

```bash
# 在虚拟机中
cd /home/warmvein
git clone https://github.com/YueX404/warmvein.git
cd warmvein
```

### 方式 B：SCP 从宿主机传输

在 **宿主机 PowerShell** 中：

```powershell
# 传整个项目（排除 .git）
scp -r D:\YY warmvein@192.168.x.x:/home/warmvein/warmvein
```

### 方式 C：VMware 共享文件夹

1. VMware → 虚拟机设置 → 选项 → 共享文件夹 → 添加 `D:\YY`
2. 在虚拟机中挂载：
```bash
sudo mkdir -p /mnt/hgfs
sudo vmhgfs-fuse .host:/ /mnt/hgfs -o allow_other
cp -r /mnt/hgfs/YY /home/warmvein/warmvein
```

### 确认文件完整

```bash
ls -la /home/warmvein/warmvein/
# 应看到：CLAUDE.md README.md docker/ src/ config/ docs/ ...
```

## 6. 部署中间件（Docker Compose）

### 6.1 进入 docker 目录

```bash
cd /home/warmvein/warmvein/docker
```

### 6.2 确认 VM 优化版配置

本项目包含两个 docker-compose 文件：

| 文件 | 用途 |
|---|---|
| `docker-compose.yml` | 开发机原始版（JVM 堆大、含 Kibana，16GB+机器用） |
| **`docker-compose-vm.yml`** | **虚拟机优化版（JVM 堆压缩、去掉 Kibana、加 MySQL/Redis，8GB 机器用）** |

**虚拟机部署使用 `docker-compose-vm.yml`**。

### 6.3 复制 VM 版配置

```bash
cp docker-compose-vm.yml docker-compose.yml
```

### 6.4 创建必要的数据目录

```bash
mkdir -p /home/warmvein/warmvein/data/{logs,hive,spark}
```

### 6.5 启动所有服务

```bash
# 首次启动（拉取镜像，约 5-10 分钟）
docker compose up -d
```

> ⚠ 首次需要下载约 **3-4 GB** 镜像，取决于网络速度。如果网络慢，可以先单独拉取：
> ```bash
> docker pull confluentinc/cp-zookeeper:7.4.0
> docker pull confluentinc/cp-kafka:7.4.0
> docker pull apache/hadoop:3.3.6
> docker pull postgres:13
> docker pull apache/hive:3.1.3
> docker pull docker.elastic.co/elasticsearch/elasticsearch:7.17.0
> docker.elastic.co/logstash/logstash:7.17.0
> docker pull apache/spark:3.3.3
> docker pull mysql:8.0
> docker pull redis:7-alpine
> ```

### 6.6 查看启动状态

```bash
# 查看所有容器状态
docker compose ps

# 查看实时日志（等约2-3分钟，看是否全部 healthy）
docker compose logs -f --tail=50
```

启动顺序大约为：
1. ZooKeeper → Kafka（约 30 秒）
2. Hadoop NameNode → DataNode（约 1 分钟）
3. PostgreSQL → Hive Metastore → Hive Server2（约 2 分钟）
4. Elasticsearch → Logstash（约 30 秒）
5. Spark Master → Worker（约 30 秒）
6. MySQL + Redis（约 10 秒）

## 7. 初始化数据库

### 7.1 MySQL 初始化

MySQL 容器启动后，会自动执行 `config/mysql/heat_init.sql`（通过 `docker-entrypoint-initdb.d`）。

验证：

```bash
docker exec -it mysql mysql -u root -pchangeme -e "SHOW DATABASES;"
# 应看到 heat_platform 数据库

docker exec -it mysql mysql -u root -pchangeme -e "USE heat_platform; SHOW TABLES;"
# 应看到 md_station, md_user, biz_alarm 等表
```

### 7.2 Hive 初始化

Hive Metastore 在启动时已自动执行 `schematool -initSchema`，验证：

```bash
# 用 beeline 测试连接
docker exec -it hive-server beeline -u 'jdbc:hive2://localhost:10000' -e "SHOW DATABASES;"
# 应看到 ods, dwd, dws, ads 等数据库
```

### 7.3 创建供热数仓表

```bash
# 在宿主机或虚拟机中，用 spark-submit 执行 Hive DDL
docker exec -it spark-master spark-submit \
  --master spark://spark-master:7077 \
  /opt/spark/work-dir/src/python/heat_spark_analysis.py 2026-08-31
```

或直接用 Hive CLI 创建表（推荐）：

```bash
docker exec -it hive-server hive -e "
CREATE DATABASE IF NOT EXISTS ods;
CREATE DATABASE IF NOT EXISTS dwd;
CREATE DATABASE IF NOT EXISTS dws;
CREATE DATABASE IF NOT EXISTS ads;
"
```

### 7.4 Redis 验证

```bash
docker exec -it redis redis-cli ping
# PONG
```

## 8. 验证所有服务

运行以下检查脚本：

```bash
echo "=== ZooKeeper ===" && nc -z localhost 2181 && echo "OK" || echo "FAIL"
echo "=== Kafka ===" && docker exec kafka kafka-broker-api-versions --bootstrap-server localhost:9092 >/dev/null 2>&1 && echo "OK" || echo "FAIL"
echo "=== HDFS ===" && curl -s http://localhost:9870 >/dev/null && echo "OK" || echo "FAIL"
echo "=== Hive Metastore ===" && nc -z localhost 9083 && echo "OK" || echo "FAIL"
echo "=== Hive Server2 ===" && nc -z localhost 10000 && echo "OK" || echo "FAIL"
echo "=== Elasticsearch ===" && curl -s http://localhost:9200 | grep -q "cluster_name" && echo "OK" || echo "FAIL"
echo "=== Spark Master ===" && curl -s http://localhost:8080 >/dev/null && echo "OK" || echo "FAIL"
echo "=== MySQL ===" && docker exec mysql mysqladmin ping -h localhost && echo "OK" || echo "FAIL"
echo "=== Redis ===" && docker exec redis redis-cli ping | grep -q PONG && echo "OK" || echo "FAIL"
```

预期输出：全部显示 `OK`。

## 9. 常用运维命令

```bash
# 查看所有容器状态
docker compose ps

# 查看某个服务日志（实时跟踪）
docker compose logs -f kafka

docker system df

# 清理无用镜像/容器
docker system prune -f
```

## 10. 故障排查

### 问题 1：OOM Killed（容器被系统杀死）

```bash
# 检查容器退出码
docker inspect <container> --format='{{.State.OOMKilled}}'
# 如果为 true，说明内存超限

# 解决方案：进一步压低 JVM 堆
# 编辑 docker-compose-vm.yml，将对应服务的 memory limit 和 heap 降低
```

### 问题 2：Hive Metastore 启动慢/失败

```bash
# Hive Metastore 依赖 Hadoop，可能需要等待 Hadoop 完全就绪
docker compose logs hadoop-namenode | grep "STARTED"
# 看到 Hadoop 启动完成后再重启 Hive
docker compose restart hive-metastore
```

### 问题 3：Kafka 无法连接

```bash
# 检查 Kafka 日志
docker compose logs kafka | tail -20

# 确认 ZooKeeper 健康
docker exec kafka kafka-broker-api-versions --bootstrap-server localhost:9092
```

### 问题 4：宿主机无法访问虚拟机端口

1. 检查 VMware NAT 端口转发是否配置正确
2. 检查虚拟机防火墙：
```bash
sudo ufw status
# 如果是 active，放行需要的端口：
sudo ufw allow 9092/tcp
sudo ufw allow 3306/tcp
# 或直接关闭防火墙（开发环境）：
sudo ufw disable
```

### 问题 5：磁盘空间不足

```bash
# 查看 Docker 磁盘占用
docker system df

# 清理无用镜像
docker image prune -a -f

# 清理已停止的容器
docker container prune -f
```

### 问题 6：HDFS 容量不足

HDFS 默认 DataNode 存储目录为容器内部，容器重启后数据保留。如需扩容：

```bash
# 在 docker-compose-vm.yml 中为 hadoop-datanode 添加 volume 映射
volumes:
  - /data/hadoop:/hadoop/dfs/data
```
