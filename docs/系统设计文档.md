# 安塞区城市安全生命线管网 AI 智慧平台 — 系统设计文档

> 版本：v2026.08.31-系统设计
> 范围：供暖管网智慧运行核心闭环切片（含短信通知）
> 说明：本设计在现有 `src/python` 工业设备监控框架（FastAPI+Kafka+Spark+Hive+ES+sklearn+ECharts）基础上改造为供热域，最大化复用现有代码骨架。

---

## 项目命名

- **对外品牌名**：**暖脉 AI 智慧供热平台**（简称「暖脉」）
  - 「暖」对应供热业务，「脉」对应城市生命线管网（如血管般输送热量）。
- **英文 codename**：`warmvein`（代码仓库、技术文档统一使用）
- **标语参考**：暖脉贯通，城市不冷。
- **命名取舍**：备选含「城暖 / 热脉 / 智暖 / 安暖」，最终选「暖脉」因其兼顾供热属性与生命线隐喻，对外易记、对内易延展（如孪生仿真可称「暖脉·孪生」、能效模块称「暖脉·能效」）。

## 1. 设计目标与原则

- **闭环优先**：以供暖主模块为中心，配套模块补齐"感知→预警→预报→预案→工单→核验"闭环，不做与主模块无关的零散功能。
- **复用优先**：沿用现有 Kafka Topic、Hive 分层（ODS/DWD/DWS/ADS）、Spark 分析、sklearn 模型、FastAPI 服务、ECharts 大屏骨架，仅替换领域模型与指标。
- **分层解耦**：采集/计算/存储/AI/服务/展现分层，接口契约化，便于后续扩展供水/燃气等域。
- **安全合规**：横切等保三级、统一权限、全量审计。

## 2. 总体架构

### 2.1 技术架构分层

```
展现层      大屏(ECharts/Vue3) · 运维APP/移动端(Vue3+TS) · 管理后台
            │  HTTPS / 统一API网关(鉴权+限流+审计)
服务层      FastAPI 供热平台服务(监测/预警/预报/预案/工单/短信/孪生仿真)
            │
AI层        Python(sklearn): 异常检测·剩余寿命·用热异常 · 规则引擎: 四级预警/冻堵预报
            │
计算层      Spark(ODS→DWD→DWS→ADS): 水力平衡·热损耗·能效 · Flink/Stream 实时指标(可选)
            │
接入层      Kafka(device-sensor-topic / device-alarm-topic) ← 采集器/PLC/传感器
            │  Logstash → ES(检索) ; Spark → Hive(数仓)
存储层      Hive(数仓分层) · MySQL(主数据/业务) · Redis(缓存/会话) · ES(时序检索) · MinIO(模型/文件)
感知层      供热传感器(温/压/流/腐蚀/泄漏/定位) · 换热站PLC · 气象 · GIS/BIM
```

### 4.2 业务库（MySQL，新增主数据与业务表）

- Redis：`alarm:latest:{stationId}`、会话 token、字典缓存、短信限流计数。

## 5. 核心模块设计

### 5.1 2.2 供暖管网智慧运行
- 监测：实时指标从 `dwd.heat_sensor_detail` 出，GIS 点位来自 `md_pipe`+GIS。
- 水力平衡：见 §6.1。
- 换热站智能控制：见 §6.3 气候补偿，控制指令写 `biz_console_action` 并下发 PLC（或人工确认）。
- 热损耗核算：见 §6.2。
- 分户异常：见 §6.5。
- 冻堵预报：见 §6.4。
- 停暖恢复仿真：基于数字孪生温度场求解（§5.7 / §6.6）。

### 5.2 4.1 预警引擎
- 规则表驱动：阈值/趋势/扩散模型触发；四级映射（蓝=轻微/黄=1-3月/橙=1月内/红=72h 内）。
- 降噪：同 station+同类告警 5min 窗口聚合为一条。
- 根因：根据触发指标打标签（腐蚀/压力/冻堵/偷热）。
- 推送：事件总线发布 `AlarmEvent` → 大屏/APP/工作群/短信消费。

### 5.3 4.2 预报与寿命预测
- 剩余寿命：`L_remain = (W_current − W_min) / v_corrosion`（年）。
- 周期预报：主干/支干/支线分级提前量；冻堵结合气象预报（§6.4）。

### 5.4 8.x 能效与节能
- 能效指标核算（热源电耗/单位供热能耗）；对标同区域均值；AI 调节策略（气候补偿+变频）写入控制回路。

### 5.5 9.x 工单与巡检
- 工单状态机：待派→已派→已接→处置中→待核验→已销号；超时逐级升级。
- 派单规则：最近站点 + 技能匹配 + 忙闲负载。

### 5.6 5.1 预案
- 预案结构化为节点（动作/责任主体/资源）；预警→匹配→启动；冻堵预案联动 §6.4 自动提温/加流。

### 5.7 10.x 数字孪生与仿真
- 三维模型：GIS+BIM 轻量化（three.js/Cesium），Web 加载。
- 热力仿真：一维管网水力-热力耦合稳态求解（供回水温度/流量分布）。
- 停暖恢复仿真：初始降温态→逐步升温，预测达标时间与曲线（§6.6）。

### 5.8 短信通知（新增）
- `SMSService` 抽象接口 `send(templateCode, phones, vars)`，具体实现 `AliyunSMSSender`/`TencentSMSSender`/`LocalMockSender` 由配置切换。
- 模板变量填充 + 手机号脱敏 + 发送限流（Redis 计数）+ 失败重试（≤3 次，指数退避）+ 熔断（连续失败超阈值暂停）。
- 订阅与免打扰：公众用户按 `md_user.sms_subscribe` 开关；责任人按班次免扰时段。

### 5.9 14.x 系统支撑（横切）
- 统一身份：多租户 + RBAC 三级权限 + SSO。
- 监控：服务/容器/DB/中间件心跳；设备在线率。
- 审计：操作日志 + 系统日志 → 审计报表。
- 等保三级：TLS、数据分级分类、脱敏、加密存储、定期自查。

## 6. 核心算法设计

### 6.1 热网水力平衡
```
β_i = G_actual_i / G_design_i           # 支路平衡度
失衡判定: β_i < 0.9 或 β_i > 1.1
调节建议: 开度Δ = (1 - β_i) * 基准开度; 必要时调泵频
```

### 6.2 热损耗精准核算
```
Q_loss = K * π * D * L * (T_avg_pipe - T_ambient)   # W
T_avg_pipe = (Tg + Th) / 2
高损判定: Q_loss > Q_loss_threshold(按管径/保温等级查表)
```

### 6.3 换热站气候补偿（质调节）
```
Tg_set = tn + (Tg_d - tn) * (tw - tn) / (tw_d - tn)
tn = 18℃(室内设计)  Tg_d = 设计供水温度(如 75℃)
tw_d = 设计室外温度(安塞约 -9℃，可配置)
th_set = Tg_set - ΔT_design
下发: 调节一次/二次网调节阀开度与循环泵频率
```

### 6.4 冻堵风险预报
```
risk = 0
if T_supply < 5℃ and tw < 0℃: risk = high
elif T_supply < 10℃ and tw < -5℃: risk = medium
elif velocity < v_min: risk = medium   # 流速过低局部冻结
输出: risk_level + 提前时长(结合气象预报) + 建议(提温/加流)
```

### 6.5 分户用热异常识别
```
同区域均值 μ, 标准差 σ
流量_z = (G_user - μ_G)/σ_G
if 室温<18 and G正常: 疑似堵塞/不热
if G_user > μ+2σ: 疑似偷热
if 回水温度异常低且流量大: 疑似私自放水
```

### 6.6 剩余寿命与停暖恢复仿真
```
剩余寿命(年) L = (W_current - W_min)/v_corrosion
停暖恢复仿真: 离散时间步，管网节点温度 T(t+1)=f(T(t), 供水温度曲线, 散热, 流量)
收敛判据: 所有用户室温 ≥ 18℃ → 输出达标时间 t_reach
```

### 6.7 ML 模型（复用 sklearn 流程）
- 异常检测：IsolationForest（供热参数多维）
- 用热异常：RandomForestClassifier（偷热/放水/不热三分类）
- 剩余寿命回归：RandomForestRegressor（输入腐蚀速率/壁厚/工况）

## 7. 安全与等保三级设计
- 传输：全站 HTTPS/TLS；Kafka 启用 SASL+SSL（可选）。
- 存储：MySQL/Redis 敏感字段加密；密码/密钥走环境变量/配置中心，禁止硬编码。
- 数据：分级分类、手机号脱敏（138****1234）、访问审计。
- 应用：所有外部输入类型/长度/格式/合法性校验；参数化查询防注入；统一错误码不暴露栈信息；防 XSS 输出转义。
- 管理：定期等保自查、弱口令检测、日志留存 ≥ 6 个月。
